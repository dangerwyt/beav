`BEAV_SINGLE_DAEMON=1`，web 与桌面端**共用同一个 daemon 与同一个 store**），
之后开始真机联调，连环暴露出一串问题，逐个定位并修复。

**这一长串问题的共同点**：症状都指向「平台抓不到 / 数据丢了」，
但根因全在**落库、归属、配置解析、沙箱**这几层，跟平台本身无关。

### 转写的两种配法（二选一，**别混用**）

| | 地址 | Key | 模型名 | 协议 |
|---|---|---|---|---|
| **直连 ElevenLabs** | `https://api.elevenlabs.io/v1/speech-to-text` | ElevenLabs key | `scribe_v2` | ElevenLabs（`xi-api-key` + `model_id`） |
| **走 relayrouter 中转** | relayrouter 的 baseURL | relayrouter key | `qwen3-asr-flash-filetrans` | OpenAI 兼容（`Bearer` + `model`） |

⚠️ 协议是**按域名自动判**的（`is_elevenlabs_endpoint` = 地址含 `elevenlabs.io`）。
走中转时地址**不能**含 `elevenlabs.io`，否则会用错协议。

设置界面里「转录」一栏下方有**自定义转写服务**的三个输入框（地址 / Key / 模型名），
与供应商下拉二选一。地址填 `elevenlabs.io` 时模型名会**自动绑定** `scribe_v2`。

### 其余模型的配置

把设置里的**「默认供应商」改成 relayrouter 那个源**即可 ——
聊天 / 图片 / 视频 / 嵌入 / 语音都会落到它。
（转写是**独立路径**，不受这个默认值影响。）

## 四、关键约定（改这块代码前必读）

完整解释见 [monitor-pipeline-pitfalls.md](/desktop/docs/monitor-pipeline-pitfalls.md)，这里是速查：

1. **`make_id` 必须带进程内序号** —— 只用毫秒时间戳会在批量写入时撞号，
   而落库是「按 id 找位置 → 找到就覆盖」，于是**静默丢数据**（症状：抓到 47 只存 5，
   且每次剩的条数都不同）。
2. **落库去重必须带归属（owner）** —— 只按裸 URL 全局去重会让后抓的人抢走先抓的记录。
   owner 取**监控项的 owner**，不是当前请求的 owner（定时任务线程里没有请求身份 = admin）。
3. **`watch_id` 不能无条件覆盖** —— 已有归属就保留；原监控项被删了才重新分配。
4. **macOS 沙箱白名单不含应用工作区** —— 工作区内的媒体文件要用 `Command::new` 直连，
   走 CLI 沙箱会拿到 EPERM（"Operation not permitted"），看着像文件坏了。
5. **`window.confirm` 在 Tauri macOS WebView 里静默失效** —— 用项目的 `appConfirm`。
   `window.alert` 早就换过了，confirm 漏了。
6. **前端调 IPC 必须检查 `result.success`** —— 桥接层会把后端 Err 吞成 fallback 对象，
   不检查就会把失败显示成「成功但 0 条」。
7. **转写配置：专属配置优先，官方源不兜底** —— `transcription_endpoint/key` 是
   **最终生效值**，`ai_model_routes_json.transcription.sourceId` 只是**来源指针**
   （且会被前端自动回退填脏，**不可信**）。
8. **判「是不是官方服务」要看 endpoint，不能看路由指针** —— 指针被污染会让
   ElevenLabs 的模型名被强行换成 `fun-asr` → 400 unsupported_model。

## 五、环境与验证

### 服务器（macOS）

- 两个 launchd 服务：`com.beav.desktop`（桌面端）、`com.beav.web`（web 网关，端口 8090）
- `BEAV_SINGLE_DAEMON=1` → web **不 spawn 实例**，直接把 IPC 代理到桌面端的 daemon（31937），
  两者**共用同一个 store**
- store：`~/Library/Application Support/Beav/beav-state.json`（camelCase 字段名）
- 工作区：`~/.beav/`（视频在 `~/.beav/monitor-videos/`）
- 部署：`cd desktop && bash deploy/update-server.sh`
  （⚠️ 前端产物变了**必须重编 Rust**，否则桌面端仍用旧嵌入资源 → 白屏）

### 本地测试

```bash
cd desktop
npx tsc --noEmit                       # 前端类型检查
cd src-tauri && cargo check --bin beav # Rust
```

⚠️ `cargo test --bin beav` **全量会挂死**（`cli_runtime::executor::tests::background_execution_poll_transitions_from_running_to_completed`
会真起 PTY 跑 shell 再等它结束，Windows 上永远不返回）。跑全量要加 `--skip cli_runtime`。
另有 ~30 个 Windows/环境相关的**既有失败**（POSIX 路径断言、真实仓库装 skill 等），
判断有没有引入新失败，用 `git stash` 跑一次基线再 diff 失败清单。

### 改完代码的验证纪律

- Rust：`cd src-tauri && cargo check --bin beav`
- 前端：`npx tsc --noEmit`
- 改了 `src-tauri/src/tools/headless_browser.rs` 里的 CDP 注入脚本 →
  **必须**再跑 `pnpm check:embedded-js`（Rust 不校验 raw string 里的 JS 语法，
  少个括号也能编译过，只在运行时报 SyntaxError，且错误会被上层吞成「页面未解析到正文」）
- `pnpm check:architecture` 目前会因 `src/pages/Knowledge.tsx` 的既有 root event 调用失败，
  与本次改动无关，不要误判
