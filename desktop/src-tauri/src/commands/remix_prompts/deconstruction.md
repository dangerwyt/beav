# 爆款结构拆解方法论

拆解的目标不是复述内容，而是回答：**它为什么能跑起来，以及哪一部分可以被我拿走复用。**

## 一、五层拆解框架

| 层 | 要回答的问题 | 取数来源 |
| --- | --- | --- |
| 选题层 | 它切的是谁的什么需求？受众是谁、痛点是什么 | 标题 + `tags` + 大纲前 2 段 |
| 钩子层 | 前 3–15 秒靠什么留住人 | `outline` 第 1 段 + 首帧 |
| 结构层 | 内容按什么顺序铺开、分几个模块 | `outline` 全量段落时间分布 |
| 论证层 | 用什么支撑观点：案例 / 数据 / 类比 / 对比 | 转写中段 |
| 收尾层 | 结尾给什么：结论 / 行动号召 / 情绪落点 | `outline` 末段 |

## 二、钩子类型学（用于识别和复用）

| 类型 | 特征 | 适用场景 |
| --- | --- | --- |
| 痛点提问 | 开场就是一个受众会点头的问题 | 知识类、职场类 |
| 反常识断言 | 先抛一个违背直觉的结论 | 认知类、科普类 |
| 身份标签 | 点名人群（"财务人""i 人程序员"） | 垂类账号 |
| 悬念前置 | 先给结果不讲过程 | 教程、测评 |
| 数据冲击 | 用具体数字开场 | 财经、科技 |
| 场景代入 | 直接演一个具体场景 | 故事型、vlog |

识别钩子时**只看前 15 秒**，别被标题误导——标题与开场钩子常常不是一回事。

## 三、节奏分析（有 SRT 时必做）

用 `load_post.py` 的 `outline`（段落 + 起止时间）做三件事：

1. **找信息密度**：段落时长短而字数多 = 高密度区，是内容的主干。
2. **找转折点**：时长明显变长的段落通常是举例/讲故事，即「喘口气」的地方。
3. **找结构骨架**：把 30+ 个段落归并成 3–7 个模块，每个模块给一句概括。
   归并后若模块 > 9 个，说明原内容偏散，二次创作时应做减法。

对照检查：

- 前 3 秒是否有独立钩子（不是自我介绍）
- 是否每 60–90 秒有一个小高潮或转折
- 结尾是否回收开头的钩子（首尾呼应）

## 四、金句提取标准

一条可独立传播的金句至少满足以下之一：

- **反差**：打破常识（"钱不是越多越好"）
- **对仗/排比**：（"是资本，是资源，是成本，是效率，是风险"）
- **数字锚点**：带具体数字且可验证
- **身份共鸣**：说出了某群体不敢说的话

提取后必须做**去语境检查**：脱离原文是否还成立？不成立则不是金句，只是上下文产物。

## 五、数据校准：赞藏比说了什么

| 信号 | 含义 | 创作启示 |
| --- | --- | --- |
| 收藏 / 点赞 > 0.4 | 工具型、干货型，用户想存下来 | 做成清单、模板、可复用框架 |
| 收藏 / 点赞 < 0.15 | 情绪型、娱乐型，用户看完就走 | 复制情绪曲线，别做成教程 |
| 评论 / 点赞 > 0.05 | 争议型或强共鸣 | 保留争议点，结尾留钩子引讨论 |

`load_post.py` 输出的 `metrics.collectPerLike` 即该比值。
**注意**：互动数据可能为 0（采集缺失），此时跳过数据校准，只做内容层拆解，并在报告中注明。

## 六、可复用性分级（每篇必给结论）

| 级别 | 判定 | 二创动作 |
| --- | --- | --- |
| A 骨架可直接复用 | 结构清晰、行业无关 | 直接换案例换行业复用结构 |
| B 需换外壳 | 结构好但强依赖原领域 | 保留骨架，替换论据与场景 |
| C 仅取灵感 | 靠人设或热点而非结构取胜 | 只取选题角度或某一金句 |

不给这个分级的拆解报告是无效的——使用者无法据此行动。

## 七、输出要求

- 每个判断后必须附**证据**（时间码 / 原文引用 / 数据），不写空泛评价
- 引用原文一律标注时间码 `00:03:12`
- 拆解报告末尾必须有「可复用清单」小节，列出可直接拿走的 3–5 个具体元素
- 输出模板见 `assets/templates/拆解报告模板.md`
